# Getting help

Start with the [available features](README.md#what-you-can-make), [local data and recovery instructions](README.md#local-retention-backup-and-recovery), and the guides in the [documentation index](docs/README.md). [V2 validation](docs/v2/validation.md) explains browser coverage and remaining limits. V3 documents describe future work, not currently available features.

Search [existing issues](https://github.com/macopc/PicWiz/issues) before opening a [bug report or feature request](https://github.com/macopc/PicWiz/issues/new/choose). For development setup and testing, see [CONTRIBUTING.md](CONTRIBUTING.md).

A useful bug report includes the commit/version, browser and OS, local or hosted build, steps to reproduce, expected and actual behavior, and the displayed error code. Reduce the problem to a minimal example using the bundled demo or a synthetic image. Note whether it also happens in a fresh browser profile without deleting your original workspace.

Issues and attachments are public. Do not upload sensitive screenshots, raw local storage, recovery backups, clipboard contents, credentials or identifying filenames. Inspect logs and recordings before sharing them. Annotations do not securely redact an image.

Browser data is tied to its profile and origin. Maintainers cannot retrieve your local workspace or recover data erased without a backup. Back up privately before trying destructive recovery steps.

Report suspected vulnerabilities through [SECURITY.md](SECURITY.md), not public issues. Report abusive conduct through the [code of conduct](CODE_OF_CONDUCT.md).
