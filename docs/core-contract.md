# Core implementation contract

The requested exports are implemented in `lib/domain.ts`, `lib/storage.ts`, `lib/canvas.ts`, and `lib/browser.ts`. `lib/image-format.ts` shares pure raster validation between storage and import. No runtime dependencies or remote operations are used.

- Background IDs: `violet` (default), `sunset`, `ocean`, `mint`, `rose`, `midnight`, `paper`, `ink`. Padding/radius/shadow default to 96/12/36 and normalize to integers in 0–200/0–48/0–100. Sizes are exactly the requested dimensions. `dimensions(style)` includes scale.
- Store types `Source`, `Preset`, and `ExportJob`, and `STORAGE_KEY` are also exported for callers. Job kind is `download | clipboard`; pending jobs have `completedAt: null` and `error: null`; failures have a short machine error code. `AppError` is re-exported from storage. Presets contain styles only.
- `loadStore` never writes. Reload converts pending jobs to failed/interrupted in its returned value; the UI can persist that result. Unsupported/corrupt envelopes throw and remain untouched, including when a caller tries to save without first loading. Writes validate the complete schema, canonical styles, raster sources, unique IDs/names, dimensions, timestamps, and job transitions. Completed records reject changes with `job_terminal`. Helpers return independent store values.
- Load/save detect changes relative to the last read/write on the same `Storage` instance and throw `storage_conflict`. Reload explicitly adopts the other tab's state. Quota and blocked storage throw `storage_quota`/`storage_unavailable`; retry is explicit. Removing the storage key and then calling `loadStore` initializes a clean snapshot for an explicit reset.
- Imported source data URLs are at most 2,500,000 characters, and normalized images have no edge above 4096. Incoming files are capped at 25 MiB, 40,000,000 pixels, and 16,384 pixels per edge. PNG/JPEG/WebP signatures, MIME matches when a MIME is supplied, declared dimensions, and decoded dimensions are checked. Import first tries a lossless PNG; if it exceeds the storage budget, it uses WebP compression, lowers quality, then resizes if needed. Original object URLs are always revoked. Returned `image` matches the persisted raster.
- `renderComposition` requires a non-null `{width,height}` source size whenever a source is drawn. A null image draws only the background and permits `{width:0,height:0}`. The optional output overrides exact canvas dimensions for previews; padding and effects scale with output width/1600. Export omits this override to use selected size × scale.
- `copyPng` calls `clipboard.write` synchronously with a promise-backed `ClipboardItem`, and waits for PNG encoding and write completion with a 15-second timeout. Call it from the original click handler without awaiting encoding first. Denial/timeout/unavailable cases throw an `AppError` and permit an explicit download action. No clipboard/download side effect is retried automatically.
- Optional test injection is additive: image functions accept an `ImageAdapter`; `copyPng` accepts a `ClipboardAdapter` with optional `createItem`, `supports`, and `timeoutMs`; `downloadPng` accepts a `DownloadAdapter`; `canvasToPng` accepts `{timeoutMs}`. These use browser defaults when omitted. Factories and timers allow deterministic tests without a DOM or actual clipboard permissions.

Reset integration: after explicitly removing `shinyshot:store`, call `loadStore(storage)` to adopt the cleared storage snapshot before saving the new empty state. Otherwise the intentional removal is detected as a storage conflict. No UI files were changed here.

No requested API was removed or renamed. The nullable job metadata, background IDs, character budget, optional injection interfaces, and explicit terminal-job errors above resolve details left open by the brief.

- Versioned local schema initialization and upgrades live in `lib/migrations/`, beginning with migration 001. Empty version zero documents upgrade to version 1; existing version 1 documents pass through repository validation unchanged.
