# Batch / ZIP implementation contract

The public functions in `core-contract.md` are preserved. This module is browser-only at execution time; importing it has no DOM side effects. No network, persistence, or download is performed.

- `BATCH_LIMITS` keys: `sources:10`, `formats:3`, `tasks:30`, `inputBytes:150*1024*1024`, `retainedBytes:64*1024*1024`, `zipBytes:65*1024*1024`.
- `BatchTask.error` / `BatchResult.error` are canonical error-code strings or null. Each task adds `attemptId`, `path`, and optional `blob`; task `id` is the stable `${sourceIndex}:${size}` pair, independent of plan ID.
- `BatchProgress.phase` is `rendering|packaging|complete|cancelled`; `current` counts settled submitted pairs and `total` is this attempt's submitted pair count. `tasks` is always the merged ordered session list, including successes from earlier attempts. `retainedBytes` is the merged accepted PNG size.
- `BatchAdapters` overrides (all optional via `Partial<BatchAdapters>`): `importImage(file)`, `loadImage(dataUrl)`, `createCanvas()`, `renderComposition(canvas,image,sourceSize,style,output,annotations)`, `canvasToPng(canvas,{signal})`, `isPngEncoderBusy()`, `releaseImage(image)`, `releaseCanvas(canvas)`, `yieldControl()`, `createZip(entries,{signal,maxBytes})`, and `now():Date`. Default image adapters return the existing browser module image/import shapes. Tests can inject these without a DOM. `renderComposition` is synchronous; other async overrides return promises.
- Plans deep-freeze copied source metadata, annotations, style, formats and task templates; File/Blob references are immutable byte containers and reused. Retrying uses the same snapshot and stable pairs, with a fresh attempt ID and subset-derived formats. Pass the preceding `BatchResult` as `previous` when executing a retry. An incompatible previous result or a retry without its matching previous result is rejected before decode.
- A module-wide submission lock prevents overlapping `runBatch` calls. A plan object can be submitted once; reusing an attempt ID in its session is rejected. Busy native PNG encoders reject new submissions (`png_busy`); timeout/busy inside an attempt fails unstarted pairs without another encode. Native encoder settlement remains owned by `browser.ts`.
- `completed` and `failed` count only submitted pairs; cancelled pairs count as neither. A partial attempt returns `status:'failed', error:'batch_partial'` with a non-null archive. A retry whose submitted pairs all succeed has `status:'succeeded'` even when older permanent failures remain in merged `tasks`/manifest; UI derives the merged failure count from those rows. A ZIP failure returns `error:'zip_failed'` with successful PNGs preserved; counts are unchanged. Cancellation returns no archive and preserves accepted successes for explicit `packageBatchResult` after the runner settles.
- Manifest `picwiz-manifest.json` is version 2 with app, createdAt, planId, scale, attempts and entries. Entries contain stable pair ID, sourceIndex, sanitized path, size, dimensions, status, canonical error and attemptId. It excludes source data URLs, raw file bytes and annotations. Paths are `01-ascii-name/size-widthxheight.png` (60-character source stem limit); numbering makes duplicate names unique.
- `packageBatchResult(result,{signal})` reuses merged successful blobs and writes a fresh manifest/ZIP, even for cancelled results. It rejects no-success results and does not check the native encoder lock, because it never encodes. ZIP injection and clock are reused from that result's run. Before repackaging/retry packaging, the module clears the prior result's `archive` reference; the caller must also drop its archive state and revoke any object URL, as required by R2. Plans, task rows and attempts are frozen; the result wrapper stays writable for archive release.
- `createZip` uses stored ZIP32, UTF-8 names, fixed 1980-01-01 timestamps, per-entry CRC32, at most 1 MiB per read and a timer yield after each slice. It preflights all headers, data, directory and EOCD bytes against `maxBytes` (clamped to 65 MiB) before reading. It rejects duplicate/traversal/absolute paths. Reference: [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT); no APPNOTE text is reproduced.
