# PicWiz V2 PRD

状态：规格复审通过（READY WITH RISKS）；2026-10-23。负责人：本线程。V1 基线：`09179ae`。本文件定义产品结果；工程合同见 `spec.md`，视觉与交互见 `product-design.md`，证据见 `market-research.md`。

## 用户与问题

面向发布产品更新的独立开发者、产品营销与技术内容创作者。用户已截好图，接下来需要突出一个变化、复用同一风格、准备多个发布尺寸。现有版本能完成单图美化，但用户仍需重复调参、逐张下载，标注需借助别的工具。人群优先级属于产品假设，尚无访谈或转化数据。

## 决策与定位

PicWiz 是本地完成的截图发布工作台：**同一套外观，一组重点清楚、尺寸准确的发布图片**。将已有预设升级为真正可复用的外观系统；标注解释内容；社交尺寸控制构图；批量 ZIP 将重复导出收束为一次可检查的操作。

市场证据：预设、标注和尺寸能力在所研究的竞品中反复出现（并非每款均具备全部能力）；Canva 和 Snagit 证明统一效果、多尺寸打包是现有替代路径。产品判断与证据边界详见研究报告。不得宣称零上传为市场独有，也不使用未核验的市场份额或付费意愿。

## 成功标准

- 6 个内置外观可一次点击应用；自存预设最多 24 个，可更新、重命名、删除、导入导出；应用后尺寸、倍率与标注保持不变。
- 3 张截图 × 2 个尺寸，得到恰好 6 张尺寸准确且命名唯一的 PNG 和一个清单，以一个 ZIP 下载。
- 箭头、矩形、文字可以添加、选择、移动、修改、删除、撤销和重做；切换画布尺寸后仍指向同一截图位置。
- 六个尺寸 × 两种倍率的导出逐项验证像素尺寸，当前图在预览、下载、剪贴板、批量中复用同一渲染器。
- 已有 4K 单图导入 <1 秒、三个样式滑杆重绘 <100ms 的 Chromium 验收继续通过。批量吞吐记录实际耗时，不把工作站基准宣传为所有手机保证。
- 390×844 视口和键盘路径可完成预设、标注、选尺寸和批量下载；无横向溢出。
- 任何用户图片、标注、预设 JSON、ZIP 内容均不发送到服务器。所有网络检查采用隔离的合成输入。

首次成功导出的用户占比、首次导出时间、预设复用率与批量使用率是后续研究指标，目标待真实试用确认。V2 不安装分析脚本，不默认采集行为；用自动化基准和自愿测试记录验证。

## 范围

P0：PicWiz 改名；本地 V1→V2 兼容迁移；外观预设库；三种可编辑标注；六种构图尺寸；有进度、取消、部分失败和失败项重试的批量 PNG ZIP；完整错误与空状态；测试与文档。

P1（本轮仍交付）：预设文件导入导出、真实渲染的中性缩略图、键盘编辑与有限的标注撤销历史、Chromium/Firefox/WebKit 测试配置与实际运行记录。

本轮排除：模板内容/市场、3D、视频、账号、云存储、团队、截图采集、任意尺寸、照片编辑、敏感信息自动识别/脱敏、多项目库、商业收费。后续四个功能只在 V2 完成后进行方案分析，等待用户决策，不提前实现。

## 主流程

1. 选择/拖放/粘贴截图 → 点击内置外观或自存预设 → 调整 → 添加标注 → 选择尺寸 → 下载或复制。
2. 保存自己的外观 → 新截图 → 打开外观库并应用 → 内容与输出尺寸互不干扰。
3. 打开批量导出 → 可包含当前图（及它的标注），添加其他源图 → 选择 1–3 种尺寸 → 审核 N×M 张结果和当前风格 → Prepare ZIP → 查看逐项状态 → Download ZIP。
4. 单项失败保留成功项；可下载部分结果，并只重试失败项。取消停止后续任务，不产生自动下载。重试用原快照；修改配置会开始新的批次。

## 发布与回退

先保留 V1 Git 基线，再实现 schema v2 和 UI。过渡只读取旧键并在新键提交完整有效文档；成功前不删除旧文档。代码与存储回退路径必须可说明。通过规格评审、单元测试、跨浏览器端到端测试、生产构建和视觉验证后交付 V2；不执行公网发布或接入后续服务。

## 主要风险

localStorage 容量小，故只持久化当前图；批量源图仅在当前标签页内。浏览器 PNG 编码不能真正中断，取消语义是立即禁止后续工作及下载，等待当前有界操作收尾。ZIP 需限制总字节；超预算不能默默漏图。剪贴板权限由浏览器/OS 决定；自动化替身不能替代真机确认。预设不承担隐私遮盖功能。

## 未决事项

V2 无阻塞性产品问题，以上取舍作为本轮授权范围内的明确假设。真实用户研究、操作系统剪贴板与低内存真机基准仍需后续验证，交付记录必须坦诚标注。下一阶段 accounts 等功能的隐私、存储与费用决策保留给用户。
