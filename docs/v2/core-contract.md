# V2 shared implementation contract

This file fixes public seams for parallel implementation. `spec.md` plus R1–R5 is authoritative product behavior. Preserve existing exports unless noted. Parent owns app/components/CSS/README/CI/package. Data/render implementer owns existing lib files + annotations/migrations and unit tests except batch/zip. Batch implementer owns batch.ts/zip.ts and their tests. Browser test implementer owns tests/e2e and playwright.config.ts. Communicate API deviations in `data-contract-notes.md` / `batch-contract-notes.md`.

## Data / drawing API

- domain: `SizeId=keyof typeof SIZES`, six IDs landscape/square/portrait/story/linkedin/pinterest. `Style` existing fields, size uses SizeId. `STARTER_PRESETS:{id,name,description,style:Style}[]`; `applyLook(current:Style,look:Style):Style` preserves current size/scale; `dimensions` existing.
- annotations: `Annotation` all fields `{id,type:'arrow'|'rectangle'|'text',x,y,width,height,color,stroke:2|4|8,text,fontSize:0.022|0.03|0.045,flipX:boolean,flipY:boolean}`. `ANNOTATION_COLORS:string[]`, `createAnnotation(type,id?):Annotation`, `validateAnnotations(value:unknown):Annotation[]`, `moveAnnotation(annotation,dx,dy):Annotation` clamps. Expose `AnnotationHistory`, `createHistory(initial)`, `pushHistory(history,next)`, `undoHistory(history)`, `redoHistory(history)` for pure bounded50 history.
- canvas: existing `renderComposition(canvas,source,sourceSize,style,output?,annotations:Annotation[]=[])`; `compositionLayout(sourceSize,style,output?)` returns `{width,height,unit,imageRect:{x,y,width,height},frameRect:{x,y,width,height},radius,top,border,bottom}`. Root uses normalized imageRect to position SVG interaction layer, same geometry as PNG. Text layout helper if useful, document its API.
- storage: new `STORAGE_KEY='picwiz:store'`, `LEGACY_STORAGE_KEY='shinyshot:store'`, version2 Store adds composition.annotations. Existing load/save/createStore/addPreset/renamePreset/deletePreset/createJob/finishJob signatures stay. New `clearStore(storage):void` removes two keys and resets snapshots, no implicit write; `backupLocalData(storage):string` preserves raw JSON strings in wrapper; `updatePreset(store,id,style):Store`; `exportPresets(store):string`; `importPresets(store,json:string):{store:Store,added:number,skipped:number}`.
- jobs: add kind=batch,status=cancelled,formats:SizeId[],scale:1|2,total/completed/failed integer fields. `createBatchJob(store,formats:SizeId[],scale:1|2,total:number,id?:string):Store`; `finishBatchJob(store,id,{completed:number,failed:number,cancelled?:boolean,error?:string}):Store` handles ZIP errors with completed=total,failed0. Root guards write epochs around clearing so async jobs cannot revive erased data. Existing finishJob single counts inferred.
- browser: existing imports retain signatures. `canvasToPng(canvas,options?:{timeoutMs?:number,signal?:AbortSignal})`; global native lock remains after application timeout/cancel until native callback, `isPngEncoderBusy():boolean`, `subscribePngEncoder(listener:(busy:boolean)=>void):()=>void`. Add `downloadFile(blob:Blob,name:string):void` supporting PNG/JSON/ZIP with normalized errors/sanitized names and URL cleanup; downloadPng existing wrapper. importImage cleans original/canvas intermediates before return.

## Batch / ZIP API

`BatchSource` is `{id:string,name:string,file:File}` or `{id:string,name:string,dataUrl:string,width:number,height:number,annotations:Annotation[]}`. File entries never inherit active annotations. Source indexes stable and order preserved; current id can be 'current'.

`createBatchPlan(sources:BatchSource[],formats:SizeId[],style:Style,id?:string):BatchPlan` validates pre-decode budgets. Plan includes `id,createdAt,sources,formats,style,tasks`; tasks include stable `id` based on sourceIndex/size, `sourceIndex,size,width,height,status,error`.

`runBatch(plan,options?:{signal?:AbortSignal,onProgress?:(progress:BatchProgress)=>void,previous?:BatchResult,adapters?:...}):Promise<BatchResult>`. `BatchProgress` includes `tasks,current,total,phase,retainedBytes`. Result includes `plan,tasks` (merged ordered tasks including retained old successes), `archive:Blob|null,error:string|null,status:'succeeded'|'failed'|'cancelled',completed:number,failed:number,retainedBytes:number`. completed/failed count ONLY this plan's submitted tasks; merged successful count derives from tasks. Task status queued/running/succeeded/failed/cancelled, optional blob and attemptId. Expected per-item errors return in result, structural invalid input rejects before execution. Result respects cumulative64MiB, never returns an accepted over-budget blob.

`retryBatchPlan(result,id?):BatchPlan` submits only retryable failed pairs, same snapshot, newID, formats derived from subset. `isRetryableBatchError(code:string|null):boolean` helps UI show correct recovery; blocked encoder disables execution regardless error code. `packageBatchResult(result,options?:{signal?:AbortSignal}):Promise<Blob>` repackages merged successes only, without image decode/render, including manifest; no successes rejects. `BATCH_LIMITS` exported for UI count/byte messages. If a simpler equivalent API is needed, document immediately in batch-contract-notes.md before parent integrates.

`createZip(entries:{name:string,blob:Blob}[],options?:{signal?:AbortSignal,maxBytes?:number}):Promise<Blob>` in zip.ts. 65MiB archive cap, stored ZIP32, per-entry CRC32, bounded slices and yield for cancellation, UTF8flag. Unit interop uses dev-only fflate; independent Node zlib.crc32/header offsets for CRC verification.

## Integrated accessibility refinement
Layer buttons are named `Select annotation N: <visible caption> N` so the accessible name includes the visible label; select by the stable prefix rather than an exact bare name. Built-in look descriptions and saved-look metadata are separate from apply button labels. Recovery actions use `Backup local data` and `Session-only editing`. The text inspector reports rendered line fit/clipping using the renderer's wrapping metrics.
