# PicWiz 后续版本：产品设计提案

> 历史提案：用户已选择 D1B／D2A／D3A／D4C。当前边界以 [V3 实现规格](../v3/spec.md)为准；下文保留研究时的推荐，不构成实现授权。

2026-10-23。**待决策，不是已实现功能。** 本提案在 V2 完成后开始：V2 提交 `0704446`，110 项单元／适配器测试与 57 项实际三引擎浏览器测试通过，详见 [验收记录](../v2/validation.md)。后续不安装供应商、不建立账号、不改变图片零上传政策；需用户决定 D1–D4 后再编写最终实现规格。

## 产品判断与市场依据

继续服务“刚截好产品图、马上要发社交媒体”的个人用户。下一步应减少构图与表达的重复劳动，而非成为完整设计或视频编辑器。

截至研究日，以下是官方公开功能声明，未付费实测，也不能由此推断用户偏好、转化提升或产品内部架构：

| 官方证据（2026-10-23 访问） | 市场含义与 PicWiz 判断 |
| --- | --- |
| [Shots](https://shots.so/)提供模板、预制布局、动画预设、缩放和视频输出。 | 仅增加设备数或更多背景难以形成长期差异；模板必须降低“怎样排版”的决策成本。 |
| [BrandBird 3D](https://www.brandbird.app/3d-device-mockups)公开说明浏览器中的设备场景、相机／灯光、时间轴及 MP4；页面称使用 WebCodecs 本地编码。 | “浏览器 3D＋本地视频”已有直接竞品。PicWiz 应保持少量可理解控件、可靠尺寸和明确失败恢复，不宣称独有技术。 |
| [Rotato Web](https://app.rotato.app/)以导入设计、调整外观／尺寸／角度、渲染图片或视频为主流程。[通用模型](https://rotato.app/generic/simple-universal)不依赖特定设备外形。 | 首发通用展示模型可以保留截图主体，降低型号选择和资产管理复杂度。它不代表特定品牌设备的真实外观。 |

**机会假设：**用户更需要可重复、可信的发布流程，而非无限自由度。还没有访谈证明模板类别、3D 付费意愿、视频使用频率或账号同步需求；不把竞品营销中的增长百分比当作本产品收益。建议先用 5–8 名实际发帖用户做任务测试；这是拟开展的验证，不是已完成研究。

## 四项能力各自解决什么

| 能力 | 用户任务 | 首发建议 | 成功指标／验收目标（尚未测量） |
| --- | --- | --- | --- |
| Template gallery | “我不知道怎么构图，给我一个完整起点。” | 6 个自有策展模板：更新卡／细节卡两类各 3 个编排；一个本地源图，可有同源细节放大、短标题与有限布局。 | ≥4/5 任务用户能在无引导下选模板、放图、导出；中位首次有效导出≤60秒。 |
| 3D mockups | “让这张产品图有空间感，同时读得清。” | 先一个通用手机做静态 PNG POC；3 个相机预设和有限角度／光线。浮卡、笔电在质量／预算验证后再扩。 | 目标桌面和实机完成预览、重试及精确 PNG；可读性与 GPU 预算经 POC 确认。 |
| Video exports | “做一个短动态发布图，不想学剪辑。” | 单张静态截图的 3 个动作：淡入、轻推、重点显现；3/5/8 秒、720 系列画幅、30fps 作为 POC 候选，无音频、剪辑或录屏输入。 | 下载文件解码尺寸、帧数与时长符合提交快照；不把实时播放时长当作导出完成保证。 |
| Accounts | “换电脑后，我的常用外观还在。” | 自愿登录，仅同步外观预设；匿名编辑与导出保留。 | 两个用户不能访问对方记录；过期登录不丢本地工作；导入／冲突／退出范围清楚。 |

上述数量与目标是产品预算，不是平台上限或承诺的性能。视频时长、输出像素和账号供应商的最终建议以对应技术提案为准，决策后冻结唯一规格。团队、市场、AI 生成、多人协作、完整时间轴、自动发布、默认截图云存储均不进入本轮建议范围。

## 信息架构与可执行流程

现有 `/` 仍是默认本地工作台。新增能力在需要时加载，基础导入和 PNG 路径保持直接。

| 拟议视图／URL | 主操作、次操作与可见状态 | 反馈、空白／等待／失败处理 |
| --- | --- | --- |
| `/templates?category=…&size=…` | 主：预览模板；次：筛选、查看授权；显示类别、适配比例、是否需要标题／3D。 | 服务端中性预览可读；无匹配给清除筛选；资源待载占位保留尺寸；单项失败可重试，不挡其他模板。 |
| `/templates/[slug]` | 主：Use template；次：切尺寸、返回；明确“截图保持本地”。 | 中性示例与结构说明先由服务器呈现；模板撤架给相近选择；未知版本不偷偷套最新模板。 |
| `/?template=id@version` 的模板审阅浮层 | 主：应用到工作区；次：取消；本地图仅在客户端生成预览，显示将替换的布局／标题。 | 先 staging，确认前不改当前 composition；有原图就复用，没图提示本地选图；取消与加载失败保留原作品。 |
| `/` 的 Scene 面板 | 主：选模型／角度；次：恢复相机、回到平面；显示模型名、输出比例、质量与已保存状态。 | GPU 探测中可继续 2D；不支持／context lost 给重试和 2D 回退；恢复失败不删除源图。 |
| `/` 的 Motion 面板 | 主：播放／暂停短预览；次：动作、时长、强度；显示真实输出像素、格式与静态首帧。 | reduced-motion 默认静态、用户主动播放；探测编码器失败直接说明可用格式，不出现假 MP4 按钮。 |
| `/` 的视频导出浮层 | 主：Prepare video→Download；次：取消、显式重试；显示帧进度与提交快照。 | pending／rendering／encoding／packaging／stopping／ready／failed；原生锁未释放时解释等待或重载，完成不自动下载。 |
| `/account` 与登录浮层 | 主：登录以同步外观；次：继续本地、管理本地文件；显示同步范围和会话状态。 | 邮件待确认、限流、验证码过期可恢复；不清除本地图片，不以登录挡导出；供应商不可用可继续本地。 |
| `/account/presets`、`/account/privacy` | 主：选择要同步的外观／处理冲突；次：导出账号数据、退出、删除账号。 | 空云库不覆盖本地库；状态为未同步／同步中／已同步／冲突／离线；覆盖和删除有明确范围确认。 |

模板应用后，若源图相同，现有截图坐标标注继续指向该图；模板标题是场景文字层，不混入截图标注。默认保留当前输出尺寸；模板建议尺寸在审阅时明确显示，只有用户主动选择时才变更尺寸。不得套模板时悄悄删除原标注或将其复制到其他图片。首发模板不引入多个来源的截图布局，避免提前扩张当前单图模型。

## 关键状态与边界

**模板：**catalog `draft→published→deprecated→withdrawn`，由内容维护者触发；发布版本与校验和不可变，修订生成新版本。已有作品保存引用版本；废弃提示替代项，下架禁止新用但不自动改已有作品。合法可继续分发的旧资源保留；若许可撤销或安全问题要求移除资源，保留本地场景并提供显式替换，不承诺旧资源永久可用。应用是 `preview→staged→applied`，取消回到原工作区；提供一次恢复应用前场景的明确动作。素材仅来自构建时受控清单，URL 参数只含模板 ID／版本，不含图片、文字或 data URL。

**3D：**`2d→loading→ready3d`；探测／资源失败进入 `fallback2d`，可重试；context lost 先停止渲染与导出，待恢复后验证场景完整再继续。源文件属于当前本地 composition；GPU texture、geometry、renderer 和临时帧归 Scene 会话所有，切换／关闭必须释放。相机预设不写入截图像素，PNG 必须由真正的 3D renderer 输出，再进入受限编码器。

**视频：**提交时冻结 scene、源图、尺寸、帧率、时长、编码配置与随机种子；一个导出 ID 对应一个快照。失败重试不混入编辑中的新设置。帧缓冲有上限，编码器背压阻止继续生产；取消不承诺强行中止浏览器原生工作。输出准备好才可下载；预览可掉帧，导出不得据墙钟时间跳过帧。3D 视频依赖已通过的 3D 逐帧 renderer；2D 视频可以先验证。

**账号：**所有本地内容仍属于浏览器 profile，而非自动归属当前登录人；同机换账号不能自动上传旧人的预设。登录后先比较、预览、选择导入，默认仅同步未来明确保存的外观。退出移除凭据与账号缓存，明确提示本地图片是否保留；账号删除与本地清空、已下载文件是三种不同范围。服务端每次查询／变更都验证 owner；猜 ID、搜索、同步、导出和删除使用相同边界。供应商登录成功不等于获得任意业务记录权限。

## 共用技术合同：小幅演进，避免提前建框架

决策后设计版本化 `SceneDocument`：现有 V2 style/source/annotations 可确定性升级为 2D scene；新增 templateRef、有限 layout/text slots、可选 mockup/camera 与 motion 配置。图片内容仍由本地源适配器持有。提案不是现在创建的数据库表或迁移；需冻结 schema 后另写 `003`，保留原始备份并覆盖配额／未来版本／跨标签页冲突测试。

建议只定义窄接口：`TemplateCatalog.get(id,version)`；`SceneRenderer.renderFrame(snapshot,time,target)`；`VideoEncoderAdapter.probe/encode/finalize/cancel`；若选择账号，再有 `PresetSyncRepository.list/applyChanges(expectedRevision)`。复用外观规范化、截图标注、原生编码锁、标准错误码和逐项作业记录。不要让 3D 依赖 React DOM 截屏，不在 request 生命周期里跑云视频渲染。

本地模板／3D／视频不需要 OAuth、S3 或后台队列。若选择云账号，仅增加身份与外观记录；若另行选择云视频，才新增私有原文件、真实队列／worker、短期授权 URL、签名事件去重、重试退避和数据清理。对应安全、环境变量、计费与运维成本须作为新边界显式批准。

## 视觉和交互方向

沿用 V2 的 paper／violet 工作台与 DM Sans，不另建营销首页。Gallery 用中性且可比较的构图缩略图，卡片标明“1 screenshot · editable title”，不把设备数量当作首屏卖点。Scene 面板先展示三个角度，而非暴露 Euler 角、材质节点或灯光图编辑器；高级精调收在明确展开区。Motion 用三种动作的短预览卡与一个时长控件，导出流程与现有 Prepare ZIP→Download 保持一致。

手机上 Gallery 是双列，详情与应用为可滚动整屏 sheet；3D 角度有按钮和数值替代拖动，Motion 用固定播放条和分步选择，导出不要求拖时间轴。所有交互有显式 label、可见 focus、文字状态和关闭后的焦点恢复；层列表、相机重置、静态回退都可用键盘完成。数据删除说明“删哪里、留什么”，成功前不显示已删除。

## 发布顺序与停止条件

建议顺序为 **Gallery → 3D POC／受限静态版 → 2D Video POC／受限版 → 可选 Accounts**。账号可以独立提前，但不是前三项的前置条件；3D video 必须等 3D renderer 与 2D encoder 各自通过。优先级是建议，用户可调整。

每项分为“决策→限时验证→冻结规格／复审→实现→真实设备和自动化验收→发布”。目标没通过就降规格或暂停该能力，不以静默上传换取成功。Gallery 首发要过模板版本／授权／迁移／替换保护；3D 要过 context loss、GPU 清理、读屏和精确 PNG；Video 要过独立解码、取消／迟到回调／格式探测；Accounts 要过双用户越权、会话失效、同步冲突、退出与删除恢复。

具体技术证据、可逆性与成本在 [Gallery／3D](gallery-and-3d.md)、[Video](video.md)、[Accounts](accounts.md)。统一决策入口为 [decisions.md](decisions.md)。本阶段产出到提案为止。
